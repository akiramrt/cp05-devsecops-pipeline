Nenhum commit chega em produção sem passar pelos três guardas.

Depois que uma chave de API vazou num commit público, a diretoria da Arcanjosa decretou: todo repositório precisa de um pipeline de segurança. Este é o pipeline de referência: ele barra segredos, código vulnerável e imagens com CVE crítico — e prova que barra.

Gatilhos: push e pull_request

O incidente

1

Uma chave de API foi commitada num repositório público. Robôs varrem o GitHub o tempo todo: em minutos uma credencial exposta já está sendo testada.

2

Apagar o arquivo depois não resolve: o segredo continua no histórico do Git. A única saída é revogar a chave e impedir que o próximo vazamento aconteça.

3

Decisão da diretoria: pipeline de segurança obrigatório, rodando em todo push e todo pull_request, bloqueando o merge quando algo falha.

O pipeline security.yml

Clique em cada guarda para ver o que ele procura e por que isso é perigoso.

Gitleaks — segredos no histórico

O que faz: Varre os commits enviados procurando padrões de credenciais: chaves de API, tokens, chaves privadas, senhas com alta entropia.

Por que importa: Um segredo commitado fica para sempre no histórico do Git e é coletado por robôs em minutos. Barrar antes do merge é muito mais barato do que revogar e investigar depois.

Prova 1: um commit com uma chave de API falsa faz o job gitleaks falhar.

As provas de sabotagem

Não basta montar o pipeline: cada guarda foi sabotado de propósito, num branch separado, para provar que ele barra o problema.

Prova 1 · barrado

Segredo falso → Gitleaks

Um commit adiciona uma chave de API falsa num arquivo de configuração. O job gitleaks encontra o segredo no histórico e falha, bloqueando o merge do PR.

branch sabotagem/01-gitleaks-segredo-falso

Prova 2 · apontado

eval() → Semgrep

Uma “calculadora” passa a avaliar o texto digitado pelo usuário com eval(). O job semgrep aponta o arquivo e a linha e falha.

branch sabotagem/02-semgrep-eval

Prova 3 · imagem limpa

Imagem do site → Trivy

A imagem Docker do site é construída no pipeline e escaneada pelo Trivy, que só deixa passar se não houver CVE CRITICAL com correção disponível.

branch main · bônus: sabotagem/03-trivy-imagem-vulneravel
